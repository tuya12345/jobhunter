## 四、我这一轮犯的错（如实记录）

**15 条新用例我写错了 7 处**，全部是"改对自己的用例"，**没有一处是放宽断言**：

| 错法 | 根因 |
|---|---|
| 把 `max_pages` 的**解释性注释**当成"还没删干净" | 按字符串搜源码 |
| 把 `reasoning_content` 的**docstring 散文**当成代码引用 | 只按行首 `#` 过滤，漏了 docstring |
| 把 COMPLIANCE 里"**以前写过**翻页上限、后来为什么删掉"的**复盘**当成"仍在声称" | 按"这一行有没有否定词"筛，两次误报 |
| COMPLIANCE 讲 UA 的关键那句所在段落里没有 "UA" 二字，于是**误判成没写** | 按段落取文本，没按小节 |
| 用错三个 API 名（`cache_svc` / `select_jobs_for_matching` / `UpsertResult.job`） | 凭记忆写，没先查签名 |
| 扫 `compute_cache_key` 时把 `tailor_svc` 文档里的一句**说明**当成了漏接线的调用点 | 同一个坑：没剥注释与 docstring |

**这七处是同一个根因的七次现身**：**用粗粒度的字符串判据去证明一个精确的语义性质，必然误报。**

已经用第六次的教训把判据统一换掉了：

- 查"字段还在不在" → 看 **pydantic `model_fields`**，不搜字符串；
- 查"代码里还引用没有" → **`ast` 剥掉注释与 docstring 再 `unparse`**；
- 查"配置项还在不在" → 只看**没被注释掉的行**；
- 查"文档有没有某段说明" → **按小节取文本**，不按段落；
- 查"某个调用点传没传参数" → **先剥注释/docstring，再配对括号取实参**。

> 顺带记一个**副作用**：本轮摘掉 25 处 `xfail` 标记时，
> 标记里的 `reason="ISSUE #N..."` 也一起没了，

## 五、这套流程跑下来的一个观察

三个轮次（提交 → 修复 → 验收），真正起作用的**不是**"验证会话逐条去核对"，而是：

1. **先有可证伪的断言**（哪怕是红的、是 `xfail` 的）；
2. **修好时断言自己会翻绿**，谁都不用通知谁；
3. **绊线要故意写**（"断言它还没修"），这样"修好了却没人回来改"也必须被处理；
4. **守卫自己也要被守卫**（反方向的元测试 + 变异自测），否则它就是个恒绿的空壳。

这四条在本轮全部实际发生过一次，不是理论。
