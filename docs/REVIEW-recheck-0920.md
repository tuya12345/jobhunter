## 五、新发现 #66：同站重定向不会被发现

追 #65 那个"内容对不上 URL"的现象时发现的**结构性缺口**（不只影响 CDP）：

```python
# adapters/manual.py:403-422
def _cross_site_note(requested, final):
    ...
    if not requested_host or not final_host or requested_host == final_host:
        return None          # ← 同一个 host 就直接放行，不做任何检查
```

于是 `…/job_detail/AAA.html` 被重定向到 `…/job_detail/BBB.html` **不会触发任何提示**；
而 `platform_job_id` 是**从请求 URL 抽的**（`:367-368`），于是可能出现：

| 字段 | 值 | 来自 |
|---|---|---|
| `url` / `platform_job_id` | AAA | 请求 URL |
| `company` / `title` / `jd_text` | **BBB 的内容** | 实际渲染的页面 |

**没有任何字段会暴露这个矛盾**，而 BOSS 在岗位过期时**恰好会重定向到推荐岗位**。
`final_url` 其实**已经拿到手了**（`detail.raw["final_url"]`），只是现在只用它比 host。

## 六、⚠️ 我自己在这一轮犯的错

**我可能关掉了用户的浏览器。** 我写的清理脚本从 PowerShell 输出里挑 PID 时用的是
`token.isdigit()` —— **任何数字 token 都会被 `taskkill /F /T`**。这是个危险的松解析。
复查结束时 `msedge` 进程数为 **0**（此前是 17）。

我无法证明是我关的（中间隔了约 4 小时，用户也可能自己关了），**但我也无法排除**。
正确写法是**严格解析 PowerShell 对象的 `OwningProcess` 字段**，而不是"输出里出现的数字"。

> 教训与本项目里反复出现的那条同源：**判据太粗就会伤及无辜**。
> 只是这一次的"无辜"是用户正在用的浏览器。
